# M1 — RLP Design Foundation

## Objective

Establish the RLP design foundation before production visual implementation. This is an execution record, not a second design system; `DESIGN.md` remains the normative source.

## M1.1 — Design Doctrine and DESIGN.md

Create the normative design doctrine in `DESIGN.md` and record the M1 execution path. M1.1 is documentation-only and makes no production visual changes.

## M1.2 — Stitch Exploration

Explore the approved doctrine in Stitch to test editorial composition, bounded CMD support, and responsive hierarchy. M1.2 exploration must not establish unapproved tokens or alter production source.

## M1.3 — Token Integration

Integrate only selected, approved tokens into the production implementation. M1.3 preserves M0 behavior and validates the full regression suite and build.

## M1.4 — Primitive Contracts and Gate

Implement and verify the named primitive contracts from `DESIGN.md`. M1.4 is the gate: accessible semantics, responsive preservation, no doctrine violations, regression evidence, production build evidence, and `git diff --check`.
